# 渲染与验收清单

## 1. 环境与静态审计

依次运行：

```text
python <skill>/scripts/doctor.py --project <project>
python <skill>/scripts/pipeline_state.py <project> status
python <skill>/scripts/validate_story.py <project> --stage pre-render --no-state
python <skill>/scripts/qa_typecheck.py <project>
python <skill>/scripts/static_audit.py <project> --skill <skill>
```

类型检查命令读取项目 `build/toolchain.json` 中已保存的 Node 绝对路径，并由该 Node 直接执行项目的 `node_modules/typescript/bin/tsc`；不经 `tsc.CMD`，也不重新查找 `PATH`。

搜索 Skill 与项目源码，确认不存在：

- 3:2 插画、`markerYForWidescreen`、`objectFit: 'cover'` 或其他裁切/坐标重映射。
- 非等比拉伸、自动补边、黑白阶段、彩色 wipe、文生视频、图生视频或 GIF。
- 圆圈高亮、正文场景编号、画外信息区或持续显示的标题。

比例规则只匹配独立的 `3:2` 或 `native 3:2` 表述；`13:26` 等时间戳不是图片比例，不得误报。确认 `build/duration-preflight.json` 状态为 `passed`，目标范围、真实 TTS 预计时长和当前故事输入指纹一致。

## 2. 图片与连续性

- 所有最终场景图像必须为1280×720；`image-sources.json` 必须记录每张原图、哈希、实际尺寸、比例偏差和缩放因子，且最终图片、清单记录和原图不得包含故事合同未引用的多余素材。
- 源图比例偏差不超过1.0%时允许自动稳定规格化；超过阈值的源图不得进入成片。
- 角色参考图是本故事新生成的，不含固定模板角色和图片内文字。
- 按 `visualBible` 和联系表检查主要角色的体型、脸部、毛发或发型、服装、颜色和标志性配件。
- 关键动作幕逐项核对主体、身体部位或工具、作用对象、接触方式、相对位置、运动方向和动作结果；必要的禁止替代动作没有被模型误换。普通背景和装饰不按关键动作合同过度挑剔。
- `image-generation-plan.json` 中并行批次最多三个场景；连续动作、道具状态继承、前图依赖和重试项均为串行。降级重试没有覆盖已通过图片。
- 每幕查看最终图片后确认 marker 落在正确对象上，没有遮挡字幕或离开画面。`accepted-minor` 只允许在首图加两次重试都失败后使用，必须写明偏差且不影响目标词识别、核心动作与连续性。

## 3. 关键帧与时间

先运行 `scripts/qa_keyframes.py <project>` 生成 `qa/manifest.json`、增量进度、状态帧和 `qa/target-contact-sheet.png`，再逐张目检。脚本使用单次打包和单浏览器批量出图；中断后重跑只补缺帧。它不能替代对目标对象和角色连续性的视觉判断。

- 片头中段：第一幕插画全屏、全中文标题存在，能听到标题中文读音，没有正文字幕。标题语义自然完整，像真正的儿童故事名，不是地点、物品和抽象词的悬空组合；长短标题均不截断、不换行。
- 标题音频结束后：标题画面继续保留约 `introTailSec`（默认0.6秒），音轨末尾没有人为添加声音或静音内容。
- `introAudioDurationSec + introTailSec` 后的正文首帧：标题已消失，正文画面、旁白和字幕立即开始，没有音频重叠。
- 每幕第一个目标词：按 `targetHighlights[0].start` 和累计场景帧渲染联系表，逐一核对词标与对象。
- 任选一个短词检查开始帧、约0.5秒、约1秒、约1.2秒和结束后一帧：词标从发音开始，至少持续 `targetVisualDurationSec`，短词默认约24帧；真实发音超过配置时持续到发音结束。
- `targetPauseSec = 0` 时没有额外静音，词标仍保持约1.2秒；正值停顿也不改变 `spokenDurationSec`。
- 词标只做一次约1秒的轻微呼吸式强调，缩放约 `1.00 → 1.05 → 1.00`，透明度变化很小且全程清楚，无快速明灭或高频闪烁。
- 场景末尾的词标完整显示后再切幕，只补足必要画面尾帧；视觉展示不作为整片凑时长手段。
- 字幕位于画内底部、字号克制、没有越界；词标使用默认 36px 字号和半透明背景，不完全遮挡目标物，也不与字幕重叠。相邻目标词分别可读，不出现重复词标叠加。

场景全局起始帧：

```text
ceil((introAudioDurationSec + introTailSec) * fps)
+ 前面所有场景 ceil(max(audioDurationSec, 最晚词标结束时间) * fps) 的总和
```

## 4. 音频验收

- 音轨只包含标题朗读和中文主体的中英混合旁白；目标词发音来自旁白时间线。
- 技术检查确认音轨存在、AAC 可完整解码、时长与画面匹配、没有异常长静音或截断。
- 实际听取至少四段：片头、普通叙事、目标词发音场景和高潮。确认旁白清晰，目标词读音完整，没有爆音或硬切。
- 主观试听是独立的内部状态。未发生真人试听时保持 `pending`，不得声称真人试听通过或听感已经确认；交付文案只报告“音频技术检查通过”。

## 5. 最终渲染与对抗式复核

使用 `render_story.py` 渲染后确认；脚本已经执行完整 `validate_mp4` 验收，正常流程不要重复运行独立验证：

- 最终渲染可能持续数分钟；单段调用上限至少20分钟，超过9000帧时按分段数量增加上限，并与 `render-plan.json.timeoutSec` 一致。成功或明确报错立即返回；暂时无输出或工具 yield 时继续等待真实进程结果，只有达到上限才判定超时。真实中断会记录失败状态，重新运行会清理不完整的 `.rendering.mp4` 并安全复用合格分段。

- 正常5–6分钟项目应走单次渲染；仅总帧数超过9000时按预定3000帧分段，分段清单和完成状态必须写入 `build/`。
- 恰好一路 H.264 视频和一路 AAC 音频，20fps、1280×720。
- `ffmpeg -v error -i story.mp4 -f null -` 完整解码无输出且退出码为 0。
- 从最终编码后的 MP4 抽取片头、正文首帧、目标词时刻和中段画面复核。
- 最终抽帧使用显式文件路径和确定的输出编号，不把 PowerShell 通配符交给 `LiteralPath`。FFmpeg 抽帧命令失败时先返回原始失败，只有命令成功后才逐个检查预期文件。
- 确认实际帧数等于故事时间线计算帧数，音视频时长误差不超过1帧；记录文件字节数和 SHA-256。
- 无音频理解工具时，内部主观试听保持 `pending`，不得用响度检测冒充实际听取。

交付前从失败角度检查：是否有非目标英文或目标词拼写变化、标题语义悬空、英文标题、词频不足、事件数量不匹配、关键动作误画、错误 marker、音频假停顿、词标不足1.2秒或场景尾部被截、闪烁过强、相邻词标叠加、角色漂移、并发图片混淆、图片裁切/拉伸/补边、标题尾停留缺失、标题残留，或只检查预览而未完整解码最终 MP4。
